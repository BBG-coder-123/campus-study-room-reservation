# 毕业设计说明

## 一、选题背景

随着高校教学与学习模式的不断发展，校园自习室已成为学生日常学习的重要场所之一。学生在课程学习、复习备考、写作业等过程中需要稳定的学习环境和合适的座位资源。与此同时，校园自习室的管理和座位预约问题也逐渐暴露出来：座位资源分配不透明、预约效率低、人工管理成本高，以及缺乏完善的反馈机制。

传统方式往往依赖人工登记、纸质记录或电话联系，不仅工作量大，而且存在座位冲突、资源浪费和使用效率低下等问题。为提高空间利用率、促进管理自动化，并提升学生学习体验，亟需构建一套科学、规范、可扩展的校园自习室预约系统。

## 二、系统目标

本系统的目标是在高校场景下实现一套完整的校园自习室预约与座位管理平台，兼顾学生端和管理员端功能需求，提升学校资源配置效率，并为数字化校园建设提供参考方案。

具体目标包括：

1. 实现学生预约、自习室查询和座位使用信息查询功能
2. 实现管理员对资源、预约和投诉进行统一管理功能
3. 提升座位利用率和预约成功率
4. 建立可扩展的前后端分离应用架构
5. 为毕业设计与课程展示提供完整工程化项目示例

## 三、需求分析

### 3.1 学生需求

学生需要在不出门、不排队的情况下完成：

- 查看自习室基本信息
- 查询座位状态
- 预约指定座位和时段
- 支付预约费用
- 查看预约记录与支付记录
- 查看公告和收费规则
- 提交投诉和获取处理结果
- 参与论坛交流

### 3.2 管理员需求

管理员需要能够：

- 管理用户及其状态
- 维护自习室和座位信息
- 审核预约请求
- 处理投诉信息
- 管理公告与论坛帖子
- 统计预约数据与使用情况
- 配置收费标准和审核调换请求

## 五、系统总体设计

本系统采用前后端分离架构：

- 前端负责页面展示、数据交互和用户操作
- 后端负责请求处理、校验、业务逻辑和数据访问
- 数据库负责存储用户、座位、预约等核心业务数据

这样分离设计能够减少前后端耦合，提高开发效率，并便于后续功能扩展和维护。

## 六、数据库设计概述

数据库命名为 `campus_reservation`，设计了多个核心表：

- `user`：用户信息
- `study_room`：自习室信息
- `seat`：座位信息
- `reservation`：预约记录
- `payment`：支付记录
- `notice`：公告
- `complaint`：投诉记录
- `forum_post`：论坛帖子
- `forum_comment`：论坛评论
- `pricing_rule`：收费规则
- `seat_swap_request`：座位调换请求

数据库设计遵循规范化原则，能够支撑系统的基础业务和后续扩展。

## 七、技术选型分析

### 7.1 后端技术选型

Spring Boot 3 是当前 Java 后端开发的主流框架之一，具备：

- 便捷的快捷开发能力
- 自动配置机制
- 强大的生态支持
- 与微服务、工程化开发兼容性强

MyBatis-Plus 提高了数据库访问效率，并支持代码生成与通用 CRUD，适合此类管理系统开发。

Spring Security + JWT 能有效实现认证授权，提高系统安全性和稳定性。

### 7.2 前端技术选型

Vue 3 作为前端主流框架，具备：

- 组件化开发能力
- 响应式数据绑定
- 高效渲染性能
- 易于维护和扩展

Element Plus 提供了丰富的 UI 组件，便于快速搭建管理后台和学生端页面。
